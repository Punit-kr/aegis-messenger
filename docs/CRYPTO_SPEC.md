# Aegis Cryptographic Specification

## 1. Mathematical Primitives

Aegis relies exclusively on standardized, peer-reviewed cryptographic primitives provided by the W3C Web Cryptography API:

| Primitive | Standard | Parameters | Purpose |
|---|---|---|---|
| **Diffie-Hellman** | NIST SP 800-56A | ECDH over Curve P-256 | Asymmetric key agreement and ratcheting |
| **Authenticated Encryption** | NIST SP 800-38D | AES-GCM (256-bit key, 96-bit IV, 128-bit tag) | Symmetric message and attachment confidentiality/authenticity |
| **Key Derivation** | RFC 5869 | HKDF with HMAC-SHA-256 | Derivation of root, chain, and message keys |
| **Hash Function** | FIPS 180-4 | SHA-256 and SHA-512 | Integrity checksums and safety number fingerprinting |
| **Password Hashing** | RFC 2898 | PBKDF2 (100,000 iterations, HMAC-SHA-256) | Derivation of master vault encryption key |

---

## 2. Key Hierarchy & Architecture

Each client device generates and maintains the following keypairs:

1. **Identity Key ($IK$)**: Long-term ECDH P-256 keypair representing the persistent identity of the device.
2. **Signed Pre-Key ($SPK$)**: Medium-term ECDH keypair rotated periodically (e.g. monthly).
3. **One-Time Pre-Keys ($OPK$)**: Pool of ephemeral ECDH keypairs uploaded to the relay and consumed once during session initiation.
4. **Ephemeral Key ($EK$)**: Single-use keypair generated by the initiator of an X3DH exchange.
5. **Ratchet Key ($DH$)**: Ephemeral keypair continually rotated on each turn of the Double Ratchet.

---

## 3. Session Initiation: X3DH Protocol

When Alice initiates a session with Bob:

1. Alice fetches Bob's public prekey bundle from the server: $\{IK_B, SPK_B, OPK_B\}$.
2. Alice generates an ephemeral keypair $EK_A$.
3. Alice computes:
   - $DH_1 = \text{ECDH}(IK_A, SPK_B)$
   - $DH_2 = \text{ECDH}(EK_A, IK_B)$
   - $DH_3 = \text{ECDH}(EK_A, SPK_B)$
   - $DH_4 = \text{ECDH}(EK_A, OPK_B)$ (if $OPK_B$ present)
4. Alice concatenates the DH outputs:
   $$SK = \text{HKDF-SHA256}(DH_1 \parallel DH_2 \parallel DH_3 [\parallel DH_4], \text{salt}=0^{32}, \text{info}=\text{"Aegis-X3DH-Master-Secret-V1"}, 32)$$
5. Alice attaches $IK_A$ and $EK_A$ to her initial PreKeyWhisperMessage envelope.
6. Bob derives the exact same $SK$ upon receipt by computing matching DH products.

## 4. Ongoing Messaging: Double Ratchet Algorithm

The Double Ratchet combines two ratchets:
1. **Asymmetric DH Ratchet**: Advances on every round-trip turn of the conversation, generating new DH keys to provide **Post-Compromise Security (PCS)**.
2. **Symmetric KDF Ratchet**: Advances on every sent and received message, generating single-use Message Keys ($MK$) to provide **Forward Secrecy (FS)**.

### Symmetric Step
For each message:
$$MK, CK_{i+1} = \text{HKDF-SHA256}(CK_i, \text{salt}=0^{32}, \text{info}=\text{"Aegis-Double-Ratchet-Symmetric-KDF-V1"}, 64)$$
- The plaintext is encrypted: $\text{AES-GCM-256}_{MK}(IV, \text{plaintext})$.
- The message key $MK$ is immediately shredded from memory.

### DH Ratchet Step
When a message arrives with a new ratchet key $DH_{peer}$:
1. Compute $DH_1 = \text{ECDH}(DH_{our\_priv}, DH_{peer\_pub})$.
2. Derive new Root Key and Receiving Chain Key:
   $$RK_{next}, CKr = \text{HKDF-SHA256}(DH_1, RK, \text{info}=\text{"Aegis-Double-Ratchet-Root-KDF-V1"}, 64)$$
3. Generate a fresh local keypair $DH_{our\_new}$.
4. Compute $DH_2 = \text{ECDH}(DH_{our\_new\_priv}, DH_{peer\_pub})$.
5. Derive new Root Key and Sending Chain Key:
   $$RK_{next2}, CKs = \text{HKDF-SHA256}(DH_2, RK_{next}, \text{info}=\text{"Aegis-Double-Ratchet-Root-KDF-V1"}, 64)$$

## 5. Contact Safety Number Derivation

Safety numbers provide out-of-band verification against man-in-the-middle attacks:
1. Alice's $IK_A$ and Bob's $IK_B$ are sorted lexicographically: $K_1 = \min(IK_A, IK_B)$, $K_2 = \max(IK_A, IK_B)$.
2. Compute digest:
   $$H = \text{SHA-512}(\text{"AEGIS-SAFETY-NUMBER-V1:"} \parallel \text{User}_1 \parallel K_1 \parallel \text{User}_2 \parallel K_2)$$
3. The first 24 bytes of $H$ are mapped into 12 distinct 5-digit decimal blocks:
   $$\text{Block}_i = ((H_{2i} \ll 8) \mid H_{2i+1}) \pmod{100000}$$
4. Displayed as twelve 5-digit numbers separated by spaces (e.g. `12345 67890 ...`).
5. Because identity keys are sorted lexicographically, both Alice and Bob view the **exact same 60-digit number**.
